# 2026年9月22日 内容识别：自动打标签与画面描述

未整理页新增「内容识别」：文件机上的视觉模型看缩略图 / 预览抽帧，产出**建议标签**与**中文画面描述**，人工确认后才写入素材。

## 语义边界

- 汽车库：建议标签只能落在**当前库已有标签**（十类）。个人视频库：**适用主题优先用已有名**，不够贴合可自拟；库外词进 `unmatched_tags`，用户可在未整理页一键新增并勾选。一二级分类同样先对现有树，对不上保留建议名由用户确认后新增。每次排队读取**当时**的库内标签与分类树，用户后续加词后下一轮识别会带上。
- 采纳等价于未整理页的打标语义：**替换该素材全部标签**（即移除「未整理」），不改 `material.status`。
- 描述写 `materials.description`；个人视频库另写 `keywords`、`copy_fit`、一二级分类（`library_taxonomy_nodes`）。
- **不改 NAS 物理文件名**（`stored_filename` / `file_path`），不动目录结构。
- ECS 只负责鉴权、排队、词表约束与结果落库；**推理在文件机**，读的是派生缩略图 / 预览 MP4，不搬原片。

## 数据流

```
未整理页勾选 → POST /materials/unorganized/analyze（带 X-Asset-Library）
  → nas_jobs 插入 job_type=analyze_content
  → 文件机 worker 领取：图片取缩略图一帧；视频从 preview MP4 均匀抽 3 帧（NAS_VLM_VIDEO_FRAMES）
  → 帧缩到 1024px 以内 → base64 → Ollama /api/chat（format=json，temperature=0.1）
  → POST /nas-jobs/{id}/complete
  → ECS 把标签名按当前库词表映射成 tag_id，写 material_files.metadata.ai_analysis
  → 未整理页轮询列表（有 pending 时每 8 秒）刷出建议
  → 人工「采纳建议并整理」或「填入右侧编辑区」后再应用
```

`material_files.metadata.ai_analysis` 状态：`pending` → `ready` / `failed`，采纳后 `applied`。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/materials/unorganized/analyze` | 排队识别；权限 `asset.edit_own` / `asset.edit_all`；同一文件已有 pending/running 作业时返回 409 |
| POST | `/materials/unorganized/apply-suggestions` | 逐素材采纳各自建议（替换标签 + 写描述等） |

两者都记 `record_operation_log`（`unorganized.analyze_content` / `unorganized.apply_ai_suggestions`）。
`GET /materials/unorganized` 的每项新增 `ai_analysis`。

## 文件机部署

识别跑在**媒体 worker 窗口**（`run-derivative-worker.ps1`，现在轮询 `generate_derivatives,analyze_content`），全量 worker 相应排除这两类，避免识别阻塞入库与下载。

默认走 **OpenAI 兼容接口**，不依赖 Ollama。文件机先用 cmd 起 Qwen 服务，Worker 再连 `NAS_VLM_BASE_URL`。

```bat
REM 本地 vLLM（GPU 机 / WSL 亦可）
python -m vllm.entrypoints.openai.api_server --model Qwen/Qwen2.5-VL-7B-Instruct --port 23333
```

或双击 `nas-client\run-qwen-vlm.cmd`。阿里云百炼也可：`NAS_VLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`，`NAS_VLM_MODEL=qwen-vl-plus`，`NAS_VLM_API_KEY=...`。

环境变量（`run-worker.ps1` 可用 `-VlmBaseUrl` / `-VlmModel` / `-VlmProvider` / `-VlmApiKey` 传入）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `NAS_VLM_PROVIDER` | 按 URL 推断，默认 `openai` | `openai` = vLLM / lmdeploy / 百炼；`ollama` 仅兼容旧方式 |
| `NAS_VLM_BASE_URL` | `http://127.0.0.1:23333/v1` | OpenAI 兼容根地址 |
| `NAS_VLM_MODEL` | `Qwen2.5-VL-7B-Instruct` | 与后端 `--served-model-name` / 百炼模型名一致 |
| `NAS_VLM_API_KEY` | 空 | 本地服务可空；百炼必填 |
| `NAS_VLM_VIDEO_FRAMES` | `3` | 视频抽帧数，1～8 |
| `NAS_VLM_FRAME_MAX_WIDTH` | `1024` | 送模型前的帧宽上限 |
| `NAS_VLM_TIMEOUT_SECONDS` | `300` | 单次推理超时 |

服务没起来时作业失败，卡片带连接地址，起来后再点「AI 识别内容」。

## 可替换的开源模型

- **Qwen2.5-VL**（默认）：中文强，JSON 输出稳定。
- **InternVL2.5 / InternVideo2.5**：视频多帧理解更好，部署更重。
- **MiniCPM-V**：小显存备选。
- **RAM++ / Tag2Text**：只出英文开放词表，若要用需再经 Chinese-CLIP 之类映射回本库标签，不能直接当词表真理源。
