# 2026年5月12日桌面应用封装技术说明

> **目的**：在**不改变**「浏览器 / 桌面壳 + **Next.js** + **FastAPI** + **文件机 Worker**」总体分工的前提下，为将本 Web 客户端封装为 **Windows / macOS 桌面应用**提供技术依据、风险清单与实施阶段建议。  
> **范围**：对接本仓库前端/鉴权/下载行为；**不**含商店上架、证书采购、法务合规全文。

---

## 1. 当前形态摘要

| 层级 | 实现要点 |
|------|-----------|
| UI | Next.js 15 App Router、React 19；业务请求多为 **`fetch("/api-proxy/...")`** |
| API 转发 | **`next.config.ts`**：`/api-proxy/:path*` → **`NEXT_PUBLIC_API_BASE_URL`** |
| 鉴权 | **`localStorage`**（`lcp_auth_session`）+ **Cookie** `lcp_auth_token`（**`SameSite=Lax`**）；**`middleware.ts`** 依赖 Cookie 放行除 `/`、`/login` 外的页面 |
| 大文件 | **LAN/WAN 文件机 HTTP**（票据 URL）；失败 **ECS `prepare_download` + `download-cache`** |
| 内嵌预览 | **`GET .../preview-video-url`**：返回 **H.264（`video/mp4`）** 可播地址；依赖 WebView **编解码能力**（见 §5） |

**结论**：桌面 MVP = **内嵌 WebView + 仍运行 Next（或等价 rewrite）+ 可达后端与文件机**；纯离线不可用。

---

## 2. 封装形态对比

### 2.1 Electron（Chromium + Node）

- **优点**：生态成熟、调试方便、Windows/macOS 同一技术栈；**`session.cookies`** 易对齐现有 Cookie 策略。  
- **缺点**：安装包大、内存占用高；须严格 **`contextIsolation`**、关闭渲染进程 **`nodeIntegration`**，防 XSS 升级为 RCE。  
- **适用**：要快、团队熟悉 JS/TS、需托盘/协议/下载路径等系统能力。

### 2.2 Tauri 2（Rust + 系统 WebView）

- **优点**：包体小；系统 WebView 无第二套 Chromium（Electron 除外）。  
- **缺点**：Windows 依赖 **WebView2**；macOS **WKWebView** 与策略与 Safari 演进绑定；与 Next **SSR** 集成需单独设计（静态导出 vs 本地起 Node）。  
- **适用**：对安装包体积敏感。

### 2.3 PWA「安装到桌面」

- **优点**：零壳开发成本。  
- **缺点**：非传统 `.exe`/`.app` 分发模型；**macOS** 支持弱于 Windows；仍受浏览器混合内容策略约束。

## 3. 与本仓库强耦合的对接点

### 3.1 环境变量与构建

| 变量 | 桌面注意 |
|------|-----------|
| **`NEXT_PUBLIC_API_BASE_URL`** | 构建期注入；生产指向 ECS 内网或公网 HTTPS 网关。 |
| 若去掉 Next、直连 FastAPI | 需统一替换前端所有 **`/api-proxy`** 为可配置 **`API_BASE`**，并在后端 **CORS** 放行壳来源（**不推荐 `file://` 打开**，优先 **`https://127.0.0.1:端口`** 加载前端）。 |

### 3.2 鉴权与深链

- 登录后必须 **`saveAuthSession`**：同时 **localStorage** 与 **Cookie**。壳内 **WebView 分区**须持久化，否则每次冷启动丢 Cookie → **middleware** 重定向 **`/login`**。  
- 若实现 **`lightcontent://materials/...`** 等自定义协议，打开子路径前须确保 **Cookie 已注入**当前会话。

### 3.3 下载与混合内容（Mixed Content）

- 若壳用 **HTTPS** 加载 Next，而 **`download-route`** 给出 **`http://内网文件机/...`**，浏览器/WebView 可能 **阻止混合内容**。对策包括：开发态用 **http://127.0.0.1** 加载前端、**主进程代理下载**、或文件机也上 **HTTPS**（内网证书信任链）。  
- **`download_server`** 的 **CORS** 已与浏览器 **`fetch`** 协同；桌面壳若改 origin，需同步文件机允许头。

### 3.4 上传与分片

- 逻辑与浏览器一致；企业代理、超时、MTU 问题在壳环境可能更常见，可调 **`NAS_HTTP_TIMEOUT_SECONDS`** 与前端重试策略（属运维/客户端配置）。

### 3.5 维护模式

- **`maintenance_guard`** 对 **POST/PUT/PATCH/DELETE** 返回 **423**（白名单 **`/auth/*`、`/nas-jobs/*`**）。**教程进度 POST** 不在白名单 → 维护期无法写入进度，属当前设计。

## 4. Windows 与 macOS 差异

| 主题 | Windows | macOS |
|------|---------|--------|
| WebView | **WebView2**（Evergreen） | **WKWebView** |
| 视频硬件解码 | 一般较完整（H.264） | 通常支持 H.264；**HEVC** 取决于系统/硬件 |
| 路径与编码 | 历史 **MAX_PATH**、反斜杠 | **NFD/NFC** Unicode 规范化 |
| 分发与更新 | MSI/EXE + 内置更新器常见 | **公证（Notarization）**、**Sparkle** 等 |
| 防火墙 | 首次访问内网文件机可能弹窗 | 同上 |

---

## 5. 预览视频（`preview-video-url`）与桌面壳

- 后端约定返回 **浏览器可播的 H.264 MP4**（见 **`materials.py`** 文档字符串）。  
- **Electron**：Chromium 解码链通常与 Chrome 接近；全屏/硬解仍受 GPU 黑名单与企业策略影响。  
- **Tauri / WKWebView**：以系统能力为准；若未来预览改为 **HEVC** 等，需单独验证 **macOS 旧机型**。  
- **建议**：桌面壳验收用例包含「内网 LAN 预览 URL + 公网 HTTPS 页面」组合，专门测 **混合内容** 与 **自动播放策略**（若前端使用 autoplay）。

## 6. 分阶段实施

| 阶段 | 内容 | 复杂度 |
|------|------|--------|
| **MVP** | 壳内嵌 WebView，加载 **`next start`** 同源站点；构建时配置 **`NEXT_PUBLIC_API_BASE_URL`** | 低 |
| **M2** | 抽象 **`getApiBase()`**；可选脱离 Next、直连 FastAPI + CORS | 中 |
| **M3** | 原生下载目录、自动更新、崩溃上报、单实例锁 | 中高 |
