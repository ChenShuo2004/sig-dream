# 2026年4月26日第一阶段上线与服务器重建及数据迁移手册

## 1. 先回答：服务器重建后数据怎么迁移？

可以迁移，且建议采用以下固定方案：

- **代码迁移**：GitHub 仓库重新拉取。
- **配置迁移**：恢复 `.env`（重点是 `DATABASE_URL`）。
- **数据迁移**：用 PostgreSQL 逻辑备份（`pg_dump`）+ 恢复（`psql`）。
- **结构迁移**：执行 `alembic upgrade head` 对齐数据库版本。
- **服务恢复**：`systemd` 启动 FastAPI 并做健康检查。

推荐原则：

- 代码和配置分离。
- 数据库每日备份，至少保留近 7 天。
- 每次备份后做一次可恢复性验证（不要只备份不演练）。

## 3. 迁移当天执行清单（20分钟版）

适用场景：旧服务器下线或故障，需要把业务快速迁移到新服务器。

### 3.1 旧服务器导出数据（3~5 分钟）

```bash
mkdir -p /root/db_backup
pg_dump -U postgres -h 127.0.0.1 -d light_content > /root/db_backup/light_content_$(date +%F_%H%M%S).sql
gzip /root/db_backup/light_content_*.sql
```

在本机下载备份：

```powershell
scp root@<旧服务器IP>:/root/db_backup/light_content_*.sql.gz .
```

### 3.2 新服务器准备运行环境（5~8 分钟）

```bash
ssh root@<新服务器IP>
apt update && apt upgrade -y
apt install -y git python3 python3-venv python3-pip postgresql postgresql-contrib
systemctl enable postgresql
systemctl start postgresql
sudo -u postgres psql -c "CREATE DATABASE light_content;"
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD 'postgres';"
```

### 3.3 新服务器恢复代码与依赖（3~5 分钟）

```bash
mkdir -p /root/apps
cd /root/apps
git clone git@github.com:ChenShuo2004/sig-dream.git
cd /root/apps/light_content_workflow_platform/backend
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

编辑 `.env`：

```env
DATABASE_URL=postgresql+psycopg://postgres:postgres@127.0.0.1:5432/light_content
```

### 3.4 新服务器导入备份并拉起服务（5 分钟）

本机上传备份：

```powershell
scp .\light_content_2026-04-26_093000.sql.gz root@<新服务器IP>:/root/db_backup/
```

新服务器导入：

```bash

cd /root/db_backup
gunzip light_content_2026-04-26_093000.sql.gz
psql -U postgres -h 127.0.0.1 -d light_content < light_content_2026-04-26_093000.sql
cd /root/apps/light_content_workflow_platform/backend
source .venv/bin/activate
```

## 4. 完整创建服务器操作过程（从 0 到可用）

以下以 Ubuntu 22.04 + root 用户为例。

### 3.1 新建 ECS 与安全组

- 创建阿里云 ECS（建议 2C2G 起，Ubuntu 22.04）。
- 开放安全组入方向端口：
  - `22`（SSH）
  - `8000`（FastAPI）

### 3.2 登录服务器并安装基础依赖

```bash
ssh root@<服务器IP>
apt update && apt upgrade -y
apt install -y git curl python3 python3-venv python3-pip postgresql postgresql-contrib
```

### 3.3 启用 PostgreSQL

```bash
systemctl enable postgresql
systemctl start postgresql
```

创建数据库与密码：

```bash
sudo -u postgres psql -c "CREATE DATABASE light_content;"
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD 'postgres';"
```

### 3.4 服务器配置 GitHub SSH 公钥

```bash
ssh-keygen -t ed25519 -C "aliyun-root"
eval "$(ssh-agent -s)"
ssh-add /root/.ssh/id_ed25519
cat /root/.ssh/id_ed25519.pub
```

把输出公钥加到 GitHub：

- `Settings` -> `SSH and GPG keys` -> `New SSH key`
- `Key type` 选 `Authentication Key`

验证：

```bash
ssh -T git@github.com
```

### 3.5 拉取项目并安装后端依赖

```bash
mkdir -p /root/apps
cd /root/apps
git clone git@github.com:ChenShuo2004/sig-dream.git
cd /root/apps/light_content_workflow_platform/backend

python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### 3.6 配置环境变量并迁移

```bash
cp .env.example .env
```

编辑 `.env`，设置：

```env
DATABASE_URL=postgresql+psycopg://postgres:postgres@127.0.0.1:5432/light_content
```

执行迁移：

```bash
source .venv/bin/activate
alembic -c alembic.ini upgrade head
```

### 3.7 配置 systemd 常驻服务

```bash
cat >/etc/systemd/system/light-content-api.service <<'EOF'
[Unit]
Description=Light Content Workflow FastAPI
After=network.target postgresql.service
Wants=postgresql.service

[Service]
User=root
Group=root
WorkingDirectory=/root/apps/light_content_workflow_platform/backend
Environment="PATH=/root/apps/light_content_workflow_platform/backend/.venv/bin"
ExecStart=/root/apps/light_content_workflow_platform/backend/.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable light-content-api
systemctl restart light-content-api
systemctl status light-content-api --no-pager
```

### 3.8 验收验证

服务器本机：

```bash
curl http://127.0.0.1:8000/health
```

本地电脑：

```powershell
curl http://<服务器IP>:8000/health
curl http://<服务器IP>:8000/docs
```

## 8. 常见故障速查

- `health` 返回 500：
  - 优先看 `journalctl -u light-content-api -n 120 --no-pager`
  - 常见为 `DATABASE_URL` 不通
- `Connection refused`：
  - 服务未启动或已退出
  - `systemctl status light-content-api` 查看状态
- `Repository not found`：
  - 服务器 SSH key 未加到 GitHub
