# NAS 扫描重建 ECS 元数据脚本模板

> 用途：用于“ECS 数据库损坏/丢失”后的灾备演练与应急恢复。  
> 原则：先导出当前库备份，再执行重建脚本；先写入临时表校验，再入正式表。

## 1) 建议恢复流程

1. 停止业务写入（暂停上传/删除/标签修改）。  
2. 备份当前数据库（`pg_dump`）。  
3. 扫描 NAS `originals/YYYY/MM` 目录，生成清单 CSV。  
4. 将 CSV 导入 ECS 临时表（`staging_nas_inventory`）。  
5. 用 SQL 执行“缺失补录 + 冲突校验”。  
6. 为无法自动判断的素材统一挂“未整理”标签。  
7. 启动对账任务，观察 `sync_operations` / `nas_jobs`。  

## 1.1 已拆分为可执行文件

- Python 扫描脚本：`tools/recovery/nas_scan.py`
- SQL 重建脚本：`tools/recovery/rebuild.sql`

示例命令（Windows）：

```powershell
python .\tools\recovery\nas_scan.py --nas-root "Z:\material-assets\originals" --out ".\tools\recovery\nas_inventory.csv"
```

## 2) NAS 扫描 Python 模板（生成 CSV）

```python
#!/usr/bin/env python3
import csv
import hashlib
from pathlib import Path
from datetime import datetime

NAS_ROOT = Path(r"Z:\material-assets\originals")  # 按实际挂载修改
OUT_CSV = Path("nas_inventory.csv")

def sha256_file(path: Path, chunk_size: int = 8 * 1024 * 1024) -> str:
    h = hashlib.sha256()
    with path.open("rb") as f:
        while True:
            chunk = f.read(chunk_size)
            if not chunk:
                break
            h.update(chunk)
    return h.hexdigest()

def main():
    rows = []
    for p in NAS_ROOT.rglob("*"):
        if not p.is_file():
            continue
        rel = p.relative_to(NAS_ROOT).as_posix()
        ext = p.suffix.lower().lstrip(".") or None
        stat = p.stat()
        rows.append({
            "nas_abs_path": str(p),
            "nas_rel_path": f"originals/{rel}",
            "stored_filename": p.name,
            "extension": ext or "",
            "file_size": stat.st_size,
            "sha256": sha256_file(p),
            "scanned_at": datetime.utcnow().isoformat(),
        })

    with OUT_CSV.open("w", newline="", encoding="utf-8-sig") as f:
        writer = csv.DictWriter(
            f,
            fieldnames=[
                "nas_abs_path", "nas_rel_path", "stored_filename",
                "extension", "file_size", "sha256", "scanned_at"
            ],
        )
        writer.writeheader()
        writer.writerows(rows)
    print(f"done, rows={len(rows)}, out={OUT_CSV}")

if __name__ == "__main__":
    main()
```

## 3) ECS 临时表 SQL 模板

```sql
-- 1) 临时清单表
create table if not exists staging_nas_inventory (
  id bigserial primary key,
  nas_abs_path text not null,
  nas_rel_path text not null,
  stored_filename text not null,
  extension text null,
  file_size bigint null,
  sha256 varchar(64) not null,
  scanned_at timestamp null
);

-- 2) 清空后重新导入（\copy 需在 psql 客户端执行）
truncate table staging_nas_inventory;
-- \copy staging_nas_inventory(nas_abs_path,nas_rel_path,stored_filename,extension,file_size,sha256,scanned_at)
-- from 'nas_inventory.csv' with csv header encoding 'UTF8';

-- 3) 查看同哈希冲突（需要人工确认）
select sha256, count(*)
from staging_nas_inventory
group by sha256
having count(*) > 1
order by count(*) desc;
```

## 4) 回填 materials/material_files SQL 模板

```sql
-- 注意：以下仅模板，生产执行前请先在测试库演练

-- A. 先补 materials（按 sha256 去重，title 先用文件名）
with src as (
  select distinct on (sha256)
    sha256,
    stored_filename
  from staging_nas_inventory
  order by sha256, id asc
),
ins as (
  insert into materials (id, title, description, status, download_count, uploader)
  select gen_random_uuid(), split_part(stored_filename, '.', 1), '灾备恢复导入', 'available', 0, null
  from src s
  where not exists (
    select 1
    from material_files mf
    where mf.sha256 = s.sha256 and mf.file_role = 'original'
  )
  returning id, title
)
select count(*) as inserted_materials from ins;

-- B. 再补 material_files（关联到刚创建或既有 material）
insert into material_files (
  id, material_id, file_role, storage_type,
  original_filename, stored_filename, file_path,
  extension, file_size, sha256, metadata
)
select
  gen_random_uuid(),
  m.id,
  'original',
  'nas',
  s.stored_filename,
  s.stored_filename,
  s.nas_rel_path,
  nullif(s.extension, ''),
  s.file_size,
  s.sha256,
  jsonb_build_object('recovery', true, 'source', 'nas_scan')
from staging_nas_inventory s
join materials m on m.title = split_part(s.stored_filename, '.', 1)
where not exists (
  select 1 from material_files mf
  where mf.sha256 = s.sha256 and mf.file_role = 'original'
);
```

## 5) 未整理标签兜底 SQL

```sql
-- 为无标签素材补“未整理”标签
insert into material_tags(id, material_id, tag_id)
select gen_random_uuid(), m.id, t.id
from materials m
join tags t on t.name = '未整理'
where not exists (
  select 1 from material_tags mt where mt.material_id = m.id
);
```

## 6) 恢复后校验 SQL

```sql
-- 1) 素材总量
select count(*) from materials;

-- 2) 原文件数量
select count(*) from material_files where file_role = 'original';

-- 3) 缺失哈希
select count(*) from material_files where sha256 is null or length(sha256) <> 64;

-- 4) 待对账/失败
select status, count(*) from sync_operations group by status order by status;
```

## 7) 注意事项

- 强烈建议在恢复前启用“导入前自动备份当前库”。  
- 模板 SQL 中 `materials.title` 的映射策略较简化，真实恢复可改为更稳妥的映射键（如扩展字段、日志表）。  
- 扫描脚本计算 SHA256 成本较高，大盘恢复可先并行分片扫描。
