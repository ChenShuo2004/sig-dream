结论：**下面这张表可以直接发给同事，用来做第一版素材标签补充。**

规则很简单：**只补标签，不补上传人、上传时间、文件大小、路径这些系统元数据。**

| 标准标签方向 | 示例标签                     |

| 车内部件   | 车机、方向盘、座椅、冰箱、彩电、中控屏、后排屏幕 |

## 6. 状态标签

**定义：**
描述素材当前在资产库里的管理状态。

**回答的问题：**

> 这个素材现在能不能用、处于什么管理状态？

| 状态标签  | 含义               |
| ----- | ---------------- |
| 未整理   | 新上传，标签不完整，需要后续整理 |
| 待审核   | 需要管理员确认可用性       |
| 可用    | 可以被团队正常调用        |
| 精选    | 高价值素材，优先使用       |
| 废弃    | 不建议使用，但暂不删除      |
| 侵权风险  | 可能存在版权、肖像权、平台风险  |
| 需二次确认 | 使用前需要管理员确认       |
| 已归档   | 已整理完成，作为长期资产保存   |

**注意：**

```text
状态标签主要由系统或管理员维护
普通成员可以建议，但不随意修改
```

# 四、标签命名规则

| 规则           | 示例                    |
| ------------ | --------------------- |
| 使用短名词        | 充电口、车机、乱停车争议          |
| 不写长句         | 不写“理想车主乱停车被骂”         |

| 不重复前缀        | 不写“理想汽车L9”，统一“理想L9”   |

| 品牌车型按官方名称    | 理想L9、理想L8、理想MEGA      |
| 英文缩写统一大小写    | B-roll、OTA、HUD 等统一写法  |

# 七、第一批标签补充任务

先不要补太多。第一版每类补 15～30 个就够。

| 标签大类   | 第一批目标数量 |
| ------ | ------: |
| 内容对象标签 |  30 个以内 |
| 素材形态标签 |  20 个以内 |
| 用途标签   |  20 个以内 |
| 场景标签   |  30 个以内 |
| 内容主题标签 |  30 个以内 |
| 状态标签   |  10 个以内 |

合计控制在：

```text
100～140 个标签
```

不要一开始做几百上千个。标签太多，上传时没人愿意选。

# 八、给同事的执行要求

可以直接发：

```text
这次只做素材标签分类，不讨论上传人、上传时间、文件大小、文件路径。

请按 6 类补充标签：

1. 内容对象标签：素材里有什么
2. 素材形态标签：素材是什么表现形式
3. 用途标签：素材可以用来干什么
4. 场景标签：素材发生在哪个场景
5. 内容主题标签：素材可以支撑什么选题/观点
6. 状态标签：素材当前管理状态

要求：
1. 每个标签尽量是短名词。
2. 不要写长句。
3. 不要写模糊词，比如“日常”“问题”“素材”“好用”。
4. 同一个概念只保留一个标准标签。
5. 相似叫法写到“同义词/误写”里。
6. 不确定的标签先写备注，不直接定为正式标签。
7. 每类先补 15～30 个，不求多，先求常用、清晰、可执行。
```

# 九、最终原则

标签体系第一版不要追求完整，追求：

```text
能上传
能搜索
能筛选
能复用
不混乱
```

最关键一句：

> **标签是为了让团队以后更快找到素材、调用素材、复用素材，不是为了把素材描述得无限详细。**
