# ECS 数据库备份与文件机拉取

推荐流程（**简单**）：

1. **发版集成（默认）**：执行 **`release-new-version.bat`** 时，**`deploy-oneclick.ps1`** 在**远程执行 `deploy.sh` 之前**会在 ECS 上跑一次 **`scripts/ecs-backup-db-local.sh`**，再把 **`light-content-latest.sql`** **`scp` 到本机**（与发版相同 **`SERVER_*` / `DEPLOY_SSH_*`**；输出目录为 **`BACKUP_OUTPUT_DIR`**，未设则为仓库根目录；文件名形如 **`light-content-pre-deploy-*.sql`**）。若不想每次发版都备份，在 **`local-env.bat`** 设置 **`set "DEPLOY_POST_RELEASE_DB_BACKUP=0"`**。备份失败**不会**导致发版失败（仅控制台警告）。  
2. **ECS 定时**（可选）：仍可在 ECS **`cron`** 里定时跑同一脚本，便于在非发版日保留 ECS 侧固定文件。  
3. **仅拉取、不发版**：可继续单独运行 **`pull-ecs-database-backup.bat`**（例如任务计划程序只拉不部署）。

备选（复杂）：ECS **`scp` 推送到文件机**（文件机需开 OpenSSH Server、ECS 配另一套密钥）见文末 **§备选**；脚本 **`scripts/ecs-backup-db-to-file-machine.sh`**。

## 一、推荐：ECS 本地 dump + 文件机拉取

### 1.1 ECS 一次性准备

```bash
apt-get update
apt-get install -y postgresql-client python3

export REMOTE_APP_DIR=/root/apps/light_content_workflow_platform
chmod +x "$REMOTE_APP_DIR/scripts/ecs-backup-db-local.sh"
```

手工跑一次确认：

```bash
"$REMOTE_APP_DIR/scripts/ecs-backup-db-local.sh"
ls -la /root/light-content-db-backups/light-content-latest.sql
```

### 1.2 ECS 定时（`cron`）

```bash
crontab -e
```

示例（每天 **3:15** 本机时间，按需改）：

```cron
15 3 * * * /root/apps/light_content_workflow_platform/scripts/ecs-backup-db-local.sh >> /var/log/light-content-db-backup-local.log 2>&1
```

可选：自定义目录（与拉取脚本里路径一致）：

```cron
15 3 * * * BACKUP_DIR=/root/light-content-db-backups /root/apps/light_content_workflow_platform/scripts/ecs-backup-db-local.sh >> /var/log/light-content-db-backup-local.log 2>&1
```

### 1.3 文件机拉取（本机，不发版时）

若平时只用 **`release-new-version.bat`**，一般**不必**再跑本节。仅在不发版、只要拉一份库时使用。

与 **`backup-ecs-database.bat`** 相同：配置 **`local-env.bat`**（**`SERVER_USER`**、**`SERVER_HOST`**、**`DEPLOY_SSH_IDENTITY_FILE`**、可选 **`BACKUP_OUTPUT_DIR`**）。

双击或在 cmd 中执行仓库根目录：

```text
pull-ecs-database-backup.bat
```

会在本机生成带时间戳的文件，例如 **`light-content-pulled-<ECS>-<时间>.sql`**。

若 ECS 上改了 **`BACKUP_DIR`**，在 **`local-env.bat`** 增加（路径须与 ECS 一致）：

```bat
set "ECS_BACKUP_REMOTE_FILE=/你的目录/light-content-latest.sql"
```

### 1.4 与 `start-nas-direct-services.bat` 同开「定时拉库」窗口（推荐在文件机上）

在 **`local-env.bat`** 增加：

```bat
set "NAS_START_DB_BACKUP_PULL_LOOP=1"
set "NAS_DB_BACKUP_PULL_INTERVAL_HOURS=24"
```

再运行 **`start-nas-direct-services.bat`**：除原有 worker / 下载服务 / 可选心跳窗外，会多开一个 **PowerShell** 窗口，**先立刻拉一次**，之后每隔 **`NAS_DB_BACKUP_PULL_INTERVAL_HOURS`** 小时循环执行 **`pull-ecs-database-backup.ps1`**（与单独双击 **`pull-ecs-database-backup.bat`** 相同环境变量）。**最小间隔按脚本为 1 小时**（防误配成过短）。

### 1.5 文件机「任务计划程序」仅拉库（不发版、不开 NAS 套件时）

- 操作：**创建基本任务** → 触发器选每天/每周 → 操作 **启动程序**：  
  - **程序**：`C:\Windows\System32\cmd.exe`  
  - **参数**：`/c "D:\path\to\repo\pull-ecs-database-backup.bat"`（改成你的仓库根 **`pull-ecs-database-backup.bat` 绝对路径**）  
- 勾选 **使用最高权限运行**（若 `local-env.bat` 在受保护路径）。  
- 前提：该机器已能 **`ssh`/`scp` 到 ECS**（与 **`release-new-version.bat`** 相同密钥）。

### 1.6 网络说明

文件机需能访问 **ECS 的 SSH 端口**（多为 **22**）。若 ECS 仅有公网 IP，文件机走公网即可；若要求走内网专线，自行把 **`SERVER_HOST`** 配成内网可达地址。

## 二、相关脚本索引

| 脚本 | 运行位置 | 作用 |
|------|----------|------|
| **`scripts/ecs-backup-db-local.sh`** | ECS | 写 **`light-content-latest.sql`** |
| **`deploy-oneclick.ps1`**（由 **`release-new-version.bat`** 调用） | 本机 | **远程 `deploy.sh` 之前**默认：**SSH 跑上一行脚本** + **`scp`** 到 **`BACKUP_OUTPUT_DIR`**（**`DEPLOY_POST_RELEASE_DB_BACKUP=0`** 可关） |
| **`pull-ecs-database-backup.ps1`** / **`.bat`** | 文件机或运维电脑 | 仅 **`scp` 拉取**（不发版时用） |
| **`run-ecs-db-backup-pull-loop.ps1`** | 文件机 | 由 **`start-nas-direct-services.ps1`** 在 **`NAS_START_DB_BACKUP_PULL_LOOP=1`** 时拉起，定时调用上一行 |
| **`backup-ecs-database.ps1`** / **`.bat`** | 运维电脑 | 远端 dump 到 **`/tmp`** 后直接拉回（不经由 ECS 固定路径） |
| **`scripts/ecs-backup-db-to-file-machine.sh`** | ECS | **推送** 到文件机（备选） |

## 三、备选：ECS `scp` 推送到文件机

文件机安装 **OpenSSH Server**，ECS 配置 **`BACKUP_FILE_MACHINE_SCP_DEST`** 等，使用 **`scripts/ecs-backup-db-to-file-machine.sh`**；细节见本文件历史版本或仓库内该脚本头部注释。

文档版本：以仓库脚本为准。
