

# 文件预览系统开发文档 V1

## 版本：V1.0

适用系统：轻量内容流程平台
模块名称：文件预览系统
开发优先级：高
目标：设计并实现一个高效的文件预览系统，支持视频、图片、音频、文档等文件类型的预览，并保证快速响应和良好的用户体验。

---

## 一、文件预览系统概述

### 1. 系统目标

* 提供视频、图片、音频、文档等常见文件类型的**预览功能**，让用户无需下载文件即可快速查看文件内容。
* **快速响应**：通过异步任务和懒加载，确保文件预览过程流畅，避免性能瓶颈。
* 提供灵活的 **任务队列管理**，能够处理大量素材预览任务，确保任务失败时可以自动重试或手动恢复。

---

## 二、技术方案

### 1. 文件预览的支持类型

* **视频文件**（如 `.mp4`, `.avi` 等）:

  * 提取视频的 **第一帧** 作为预览图（使用 **ffmpeg** 工具提取视频帧）。
  * **视频缩略图** 生成并存储为图片文件，展示给用户。
* **图片文件**（如 `.jpg`, `.png` 等）:

  * 生成 **标准缩略图**，供用户查看。
* **音频文件**（如 `.mp3`, `.wav` 等）:

  * 显示 **音频文件图标**，用户点击后可查看文件信息。
* **文档文件**（如 `.pdf`, `.docx`, `.pptx` 等）:

  * **PDF**：使用 **PDF.js** 生成 PDF 文件的第一页作为预览。
  * **Word / Excel**：使用 **LibreOffice** 或 **Office Web Viewer** 生成文件的首屏预览。
* **其他文件类型**（如 `.txt`, `.zip` 等）:

  * 显示 **标准文件类型图标**（.ico）。

---

### 2. 异步预览图生成

* 使用 **任务队列**（如 **Celery**）来异步处理文件预览图的生成，避免阻塞主线程。
* **任务状态管理**：每个任务（生成文件预览图）都应记录任务状态（待处理、处理中、成功、失败）。

  * 如果任务失败，支持 **自动重试** 和 **手动恢复**。

---

### 3. 队列处理与任务恢复

* **任务队列**：

  * 使用 **Celery** 作为任务队列管理系统，处理文件预览图生成任务。
  * 每个任务都将被分配一个 **唯一的任务 ID**，用于标识任务状态和处理结果。
* **任务恢复**：

  * 当预览图生成任务失败时，系统应提供 **重试机制**，可以设定最大重试次数（如 3 次）。
  * 提供 **手动恢复** 任务功能，管理员可以通过管理后台恢复失败的任务。

---

## 三、文件预览生成流程


1. **文件存储到 NAS**：首先将文件存储到 **NAS 服务器**。
2. **任务队列创建**：ECS 服务器将文件路径与任务信息推送到 **Celery 队列**中，等待预览图生成任务。
3. **缩略图生成**：

   * 对于视频文件，使用 **ffmpeg** 提取视频第一帧，生成视频缩略图。
   * 对于图片文件，使用 **Pillow** 或 **ImageMagick** 生成缩略图。
   * 对于 PDF 文件，使用 **PDF.js** 提取封面图。
   * 对于其他文件类型，使用标准的文件类型图标。
4. **文件存储与管理**：

   * 生成的预览图存储在 **NAS 服务器专门的预览图目录**，并与原始文件关联。
   * 关联规则存储在 **文件命名规则的 Markdown 文档**里，方便灾难恢复。
5. **任务状态更新**：任务完成后，更新任务状态为“**已完成**”或“**失败**”，并记录操作日志。任务日志仅存储在 **NAS**。

## 四、系统设计

### 1. 文件预览生成流程

* **任务队列创建**：在文件被存储到 NAS 服务器后，ECS 将文件路径和任务信息推送到 Celery 队列中，生成文件的预览图。
* **任务管理**：任务完成后，系统会自动更新任务状态并记录操作日志。

### 2. 缩略图生成

* **视频文件**：使用 **ffmpeg** 提取视频第一帧作为缩略图。
* **图片文件**：使用 **Pillow** 或 **ImageMagick** 生成缩略图。
* **文档文件**：对于 PDF 文件，使用 **PDF.js** 提取封面图。
* **其他文件类型**：使用标准文件类型图标。

### 3. 缩略图存储与管理

* **存储目录**：缩略图存储在 **NAS 服务器专门的预览图目录**，并与原始文件路径关联。文件命名规则将在 Markdown 文档中进行详细记录，确保文件和缩略图能够准确对应。

## 五、文件预览与操作

### 1. 视频文件

* **缩略图**：提取第一帧作为视频缩略图，展示在页面上。
* **播放**：后期可根据需求增加播放功能。

### 2. 图片文件

* **缩略图**：直接展示文件的缩略图，点击后可放大查看。

### 3. 音频文件

* **图标**：显示音频文件图标，点击后展示音频的基本信息。

### 4. 文档文件

* **PDF 文件**：通过 **PDF.js** 提取封面图并显示在页面上。
* **Word、Excel** 文件：通过 **LibreOffice** 或 **Office Web Viewer** 提取文档封面。

### 5. 其他文件类型

* **图标**：显示标准文件类型图标，如 `.zip` 显示压缩包图标，`.txt` 显示文本文档图标。

## 六、UI 设计

### 1. 右侧详情抽屉

* **文件名**：显示文件的基础信息（文件名、标签、上传时间等）。
* **预览区域**：

  * **移入回收站**：将文件移入回收站。

## 九、API 设计

### 1. 获取文件预览信息

```text
GET /api/file/preview
```

请求参数：

```json
{
  "file_id": "file12345",
  "user_id": "user6789"
}
```

返回示例：

```json
{
  "file_name": "example.mp4",
  "preview_url": "http://example.com/preview/example.mp4",
  "status": "success",
  "message": "Preview generated successfully"
}
```

### 2. 文件预览生成任务管理

```text
POST /api/preview/generate
```

请求参数：

```json
{
  "file_id": "file12345",
  "task_id": "task12345"
}
```

返回示例：

```json
{
  "task_status": "queued",
  "message": "Preview generation queued successfully"
}
```

### 3. 查询任务状态

```text
GET /api/preview/status
```

请求参数：

```json
{
  "task_id": "task12345"
}
```

返回示例：

```json
{
  "task_status": "completed",
  "preview_url": "http://example.com/preview/example.mp4"
}
```
