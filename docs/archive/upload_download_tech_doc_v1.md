
# 文件上传与下载技术实现文档 V1

## 版本：V1.0  
适用系统：轻量内容流程平台  
模块名称：文件上传与下载  
开发优先级：中  
目标：设计并实现一个高效的文件上传与下载系统，支持局域网内直接传输文件，外网访问时通过 ECS 服务器作为中介。

---

## 一、文件传输架构

### 1. 局域网内文件传输
- **局域网内访问**：当客户端 B 和 NAS 挂载机器 A 在同一局域网内时，**文件上传与下载**应通过 **局域网协议**（如 SMB、NFS、FTP 等）直接进行。
- **ECS 服务器作用**：ECS 服务器充当协调器，处理权限验证、文件上传与下载请求，但不参与实际的数据传输。

### 2. 外网访问文件传输
- **外网访问**：如果客户端 B 不在局域网内，**ECS 服务器充当中介**，协调文件的上传与下载操作。具体来说，客户端 B 通过 ECS 发起文件操作请求，ECS 负责与局域网内的电脑 A 协调，将文件从 NAS 传输到客户端 B，或者将文件从客户端 B 上传到 NAS。

---

## 二、技术实现步骤

### 1. 局域网内文件传输（A 和 B 在同一局域网）

- **步骤 1**：客户端 B 通过 HTTP 请求向 ECS 服务器发起文件上传或下载请求。
- **步骤 2**：ECS 服务器验证权限，确认客户端 B 是否有权限访问文件。
- **步骤 3**：ECS 服务器将文件操作请求转发给 **电脑 A**，要求 A 从 NAS 获取文件或将文件存入 NAS。
- **步骤 4**：电脑 A 通过 **SMB/NFS/FTP** 协议直接访问 NAS 文件系统，并将文件通过局域网传输给客户端 B，或将文件从 B 上传到 NAS。
- **步骤 5**：文件传输完成后，ECS 记录操作日志，完成文件上传或下载。

---

### 2. 外网访问文件传输（A 和 B 不在同一局域网）

- **步骤 1**：客户端 B 向 ECS 服务器发送上传或下载文件的请求。
- **步骤 2**：ECS 服务器验证权限，确认客户端 B 的权限。
- **步骤 3**：ECS 将文件操作请求转发给 **局域网内的电脑 A**，要求 A 进行文件操作。
- **步骤 4**：电脑 A 通过局域网协议（SMB、NFS、FTP 等）从 NAS 读取文件或将文件存入 NAS。
- **步骤 5**：ECS 服务器将文件从电脑 A 通过 HTTP 协议传输到客户端 B（或从客户端 B 上传到 NAS）。
- **步骤 6**：文件传输完成后，ECS 记录操作日志，完成文件上传或下载。

---

## 三、技术架构

### 1. ECS 服务器

- **角色**：作为中介服务器，处理文件上传与下载的权限验证和任务调度。
- **任务**：
  - 接收并验证客户端 B 的上传/下载请求。
  - 与局域网内的电脑 A 协调，向其请求文件操作。
  - 将文件从 A 传输到 B，或将文件从 B 上传到 A（与 NAS 交互）。
  - 记录文件操作日志。

### 2. 电脑 A（NAS 挂载机器）

- **角色**：与 NAS 直接交互，负责从 NAS 获取文件或将文件上传到 NAS。
- **任务**：
  - 通过 SMB/NFS/FTP 协议直接访问 NAS 存储。
  - 根据 ECS 服务器的请求，将文件传输到客户端 B，或将文件从客户端 B 上传到 NAS。

### 3. 客户端 B

- **角色**：发起文件上传和下载请求。
- **任务**：
  - 向 ECS 发送文件上传或下载请求。
  - 在文件传输过程中，接收文件或将文件上传到 ECS。
  - 确认文件传输的状态，并进行操作日志记录。

### 4. 文件传输协议

- **SMB/NFS/FTP**：用于局域网内的文件传输。具体使用哪个协议取决于 NAS 的配置和网络环境。
  - **SMB**：适用于 Windows 环境和混合环境（Windows 和 Linux）。
  - **NFS**：适用于 Linux 环境。
  - **FTP/SFTP**：适用于更通用的文件传输场景，可以在局域网和外网中使用。

---

## 四、详细实现流程

### 1. 文件上传（客户端 B → NAS）

- **步骤 1**：客户端 B 通过 HTTP 请求向 ECS 发送上传文件请求，ECS 进行权限校验。
- **步骤 2**：ECS 服务器将上传任务转发给电脑 A，指示其从客户端 B 获取文件并存入 NAS。
- **步骤 3**：电脑 A 通过 SMB/NFS/FTP 从客户端 B 获取文件，并存入 NAS 存储中。
- **步骤 4**：文件上传完成后，ECS 记录文件上传日志，通知客户端 B 上传完成。

### 2. 文件下载（NAS → 客户端 B）

- **步骤 1**：客户端 B 通过 HTTP 请求向 ECS 发送下载文件请求，ECS 进行权限校验。
- **步骤 2**：ECS 服务器将下载任务转发给电脑 A，要求其从 NAS 获取文件并发送给客户端 B。
- **步骤 3**：电脑 A 通过 SMB/NFS/FTP 从 NAS 获取文件并通过 HTTP 协议传输给客户端 B。
- **步骤 4**：文件下载完成后，ECS 记录文件下载日志，通知客户端 B 下载完成。

## 五、系统设计与优化

### 1. **文件上传和下载效率优化**

- **局域网内传输**：如果客户端 B 与电脑 A 在同一局域网内，文件传输将通过 **SMB/NFS/FTP** 协议直接进行，减少了通过 ECS 传输数据的瓶颈。
- **外网访问优化**：如果客户端 B 不在局域网内，则 ECS 服务器通过协调，依然保证文件操作的可靠性和顺利进行。可以通过 WebSocket 或 REST API 实现实时状态更新，减少等待时间。

### 2. **任务队列与调度**

- 采用 **任务队列**（如 Celery）来管理文件上传和下载任务，确保文件操作的顺序性和一致性。
- 任务队列可以实现 **异步操作**，将文件传输任务放入队列中，后台工作者处理文件操作，不会阻塞主线程。

## 六、部署架构

### 1. ECS 服务器

- 部署环境：在 ECS 上部署 FastAPI（或者其他 Web 框架），实现 API 接口。
- 文件传输中介：ECS 服务器通过 SMB/NFS/FTP 协议与电脑 A 进行通信，将文件上传或下载到客户端 B。

### 2. 电脑 A（NAS 挂载机器）

- 部署环境：在局域网内，电脑 A 挂载 NAS 文件系统，负责直接与 NAS 进行文件操作。
- 任务执行：接收 ECS 服务器转发的文件上传和下载任务，执行文件操作。

### 3. 客户端 B

- 部署环境：客户端 B 运行 Web 客户端，发起文件上传和下载请求，通过 ECS 服务器与局域网中的电脑 A 进行数据传输。

## 七、API 设计

### 1. 上传文件请求

```text
POST /api/upload
```

请求体：

```json
{
  "file_name": "example.mp4",
  "file_size": 1048576,
  "destination": "NAS"
}
```

### 2. 下载文件请求

```text
POST /api/download
```

请求体：

```json
{
  "file_name": "example.mp4",
  "source": "NAS"
}
```

### 3. 获取文件上传/下载进度

```text
GET /api/file-status
```

返回示例：

```json
{
  "file_name": "example.mp4",
  "status": "in-progress",
  "progress": 50
}
```

## 八、给 Cursor 的开发指令

```text
请开发文件上传和下载模块，支持局域网内直接传输文件、外网访问时通过 ECS 服务器作为中介。

1. 在 ECS 服务器上部署 API 接口，验证文件上传和下载权限。
2. 使用 SMB/NFS/FTP 协议在局域网内传输文件。
3. 如果客户端 B 不在局域网内，通过 ECS 服务器作为中介，协调文件传输。
4. 使用任务队列（如 Celery）管理上传下载任务，保证文件操作的顺序性和一致性。
5. ECS 服务器记录上传下载操作日志，提供接口返回文件操作状态。

请注意，**外网访问时不通过 ECS 服务器传输文件，减少带宽占用和延迟**，ECS 只负责协调任务和记录日志。
```
