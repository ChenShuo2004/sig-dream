# 新 ECS 部署操作说明

本文说明在一台**全新的 ECS**（Debian/Ubuntu 系，已能 SSH）上，从零跑通本项目的推荐顺序、脚本入口与验收要点。  
更细的 **SSH 双密钥（本机→ECS、ECS→GitHub）** 命令级步骤见：**`2026年5月3日新ECS双密钥配置实操.md`**。  
日常发版与 `deploy-oneclick.ps1` 行为见：**`2026年4月26日更新发布流程.md`** §3。

---

## 1. 总体顺序（必读）

`restore-ecs-database.ps1`（由 **`仅导入数据库到ECS.bat`** 调用）在远端会：

- `cd <RemoteAppDir>/backend`
- 读取 **`backend/.env`** 里的 **`DATABASE_URL`**
- 使用 **`backend/.venv`** 执行 **`alembic upgrade head`**

因此 **全新 ECS 上不能「先灌库再首次发布」**（远端还没有 `backend/.env` 与 venv 时会失败）。

**推荐顺序：**

| 步骤 | 做什么 | 本机入口 |
|------|--------|----------|
| 1 | 本机能 SSH 到 ECS；ECS 能 `git clone`/`pull` 私仓（部署密钥） | 见 **`2026年5月3日新ECS双密钥配置实操.md`** |
| 2 | 配置 `local-env.bat`（目标 ECS、密钥、可选 token） | 复制 **`local-env.example.bat`** → **`local-env.bat`** |
| 3 | **首次一键部署**：代码、依赖、前端构建、远端 `deploy.sh`、库迁移等 | **`release-new-version.bat`** |
| 4 | **导入已有 PostgreSQL 备份**（覆盖/灌入业务数据，可选但生产迁移几乎必做） | **`仅导入数据库到ECS.bat`** |
| 5 | 文件机侧：NAS 映射、Worker、LAN 上传、可选心跳 | **`start-nas-direct-services.bat`**（在 **Windows 文件机** 上执行） |

**可选（域名走 80，不暴露 3000）**：在步骤 **3** 成功后，本机执行 **`setup-nginx-reverse-proxy.bat`**（见 **§5**）。需域名解析到 ECS、安全组放行 **80**，且 ECS 上 **`light-content-web`** 监听 **`127.0.0.1:3000`**（与脚本默认 `proxy_pass` 一致）。

后续仅改代码发版：重复步骤 **3** 即可；**仅改库数据** 时用步骤 **4**（不必每次发版都导库）。

---

## 2. 前置条件检查清单

- **ECS**：公网 IP 或固定入口；安全组放行 **8000**（API）、**3000**（前端，若直接对外）、**80**（若使用 **§5** Nginx 反代）、**443**（若启用 **§5.5** HTTPS）；本机到 ECS **22**（SSH）。
- **Git**：仓库在本机已 `git remote` 可推送；ECS 上使用 **SSH 地址** 克隆私仓（HTTPS 无交互令牌时易失败）。
- **PostgreSQL**：  
  - 使用 **`release-new-version.bat`** 默认 **`DEPLOY_BOOTSTRAP_POSTGRES=1`** 时，若 `.env` 里 `DATABASE_URL` 指向本机且 5432 未就绪，远端 `deploy.sh` 可能 **apt 安装 PostgreSQL** 并建库（仅适合自建库场景）。  
  - 若使用 **阿里云 RDS**，请在首次部署后把 **`backend/.env`** 中 **`DATABASE_URL`** 改成 RDS 连接串，再 **`systemctl restart light-content-api`**，并在 **`local-env.bat`** 中设置 **`DEPLOY_BOOTSTRAP_POSTGRES=0`** 避免误装本机库。
- **备份文件**：从旧环境导出的 **plain SQL**（`pg_dump`），路径供 **`仅导入数据库到ECS.bat`** 使用。

## 3. 配置 `local-env.bat`

在仓库根目录复制示例并编辑（**不要提交** `local-env.bat`）：

```bat
copy local-env.example.bat local-env.bat
```

至少建议配置（均为 **ASCII**，避免 GBK 下 cmd 解析异常）：

| 变量 | 含义 |
|------|------|
| `SERVER_USER` / `SERVER_HOST` | SSH 登录 ECS |
| `REMOTE_APP_DIR` | 远端应用目录，默认 `/root/apps/light_content_workflow_platform` |
| `DEPLOY_SSH_IDENTITY_FILE` | 本机私钥路径（`BatchMode` 下需密钥登录） |
| `DEPLOY_REMOTE_AUTO_CLONE` | 新机器无目录时 **`release-new-version.bat`** 默认 `1`，远端缺失则 `git clone` |
| `DEPLOY_BOOTSTRAP_POSTGRES` | 是否允许远端脚本在本机装 PG，RDS 场景请 `0` |
| `DEPLOY_NAS_CLIENT_TOKEN` | 与文件机 **`nas-client/nas-client-token.txt`** 首行一致；部署成功后会合并进远端 **`backend/.env`** 的 **`NAS_CLIENT_TOKEN`** 并重启 API，避免 **`nas-jobs/poll` 401** |
| `DEPLOY_PG_DUMP_SQL` | （可选）预设 SQL 全路径，供 **`仅导入数据库到ECS.bat`** 跳过交互 |
| `NGINX_SERVER_NAME` 等 **`NGINX_*`** | （可选）供 **`setup-nginx-reverse-proxy.bat`** 写 ECS 上 Nginx 反代，见 **§5** |

可选：`MIGRATE_SKIP_COMMIT=1` 仅推送/部署不本地提交；`BUILD_VERSION=...` 写入前端展示版本。

---

## 4. 首次部署：`release-new-version.bat`

1. 确认 **`local-env.bat`** 已按上一节填写。  
2. 在资源管理器中双击或在 cmd 中执行仓库根目录下的 **`release-new-version.bat`**。  
3. 等待结束：应出现 **`[OK] Deploy finished`**；窗口会 **`pause`**。

脚本会调用 **`deploy-oneclick.ps1`**：本地 `git`、推送、SSH 执行远端 **`deploy.sh`**，并做基础健康检查。  
若配置了 **`DEPLOY_NAS_CLIENT_TOKEN`**（或本机存在非占位的 **`nas-client/nas-client-token.txt`** 首行），部署成功后会 **额外 SSH 一次**，把 token 写入远端 **`NAS_CLIENT_TOKEN=`** 并 **`systemctl restart light-content-api`**。

**验收（本机浏览器或 curl）：**

- `http://<ECS公网>:8000/health` 返回 JSON 正常。  
- `http://<ECS公网>:3000/` 可打开（视安全组与监听地址而定）。

**验收（SSH 登录 ECS）：**

```bash
systemctl is-active light-content-api light-content-web
grep -n '^NAS_CLIENT_TOKEN=' /root/apps/light_content_workflow_platform/backend/.env
```

## 5. Nginx 反向代理（域名、`80` → 前端）

在 **本机 Windows**（与发版相同，已配置 **`local-env.bat`** 能 SSH 到 ECS）执行，用于：**用户通过 `http://你的域名/` 访问**，由 ECS 上 **Nginx** 监听 **80**，再反代到本机 **`127.0.0.1:3000`**（Next 默认由 **`light-content-web`** 监听，与仓库 systemd 一致）。

### 5.1 本机入口与变量

| 入口 | 说明 |
|------|------|
| **`setup-nginx-reverse-proxy.bat`** | 调用同目录 **`setup-nginx-reverse-proxy.ps1`**，经 SSH 在远端写配置并重载 Nginx |

在 **`local-env.bat`** 中除 **`SERVER_*` / `DEPLOY_SSH_*`** 外，建议增加（均为 **ASCII**）：

| 变量 | 含义 |
|------|------|
| **`NGINX_SERVER_NAME`** | Nginx 的 **`server_name`**，多个主机名用**空格**分隔，例如：`yideapi.com www.yideapi.com` |
| **`NGINX_LISTEN_PORT`** | （可选）监听端口，默认 **`80`** |
| **`NGINX_UPSTREAM_HOST`** | （可选）反代目标主机，默认 **`127.0.0.1`** |
| **`NGINX_UPSTREAM_PORT`** | （可选）反代目标端口，默认 **`3000`**（与前端 systemd 一致） |

未设置 **`NGINX_SERVER_NAME`** 时，PowerShell 会**交互提示**输入一行 `server_name`。

### 5.2 执行步骤

1. 将域名 **A 记录** 指向 ECS **公网 IP**。  
2. 云安全组 **入方向放行 TCP `NGINX_LISTEN_PORT`**（一般为 **80**）。  
3. 确认 **`release-new-version.bat`** 已成功至少一次，远端 **`light-content-web`** 为 **active**（否则反代无上游）。  
4. 在仓库根目录执行 **`setup-nginx-reverse-proxy.bat`**，等待 **`[OK] Nginx configured`**。

脚本行为概要：

- 若未安装 **nginx**，会尝试 **`apt-get`** / **`dnf`** / **`yum`** 安装（以 ECS 发行版为准）。  
- **Debian/Ubuntu**：写入 **`/etc/nginx/sites-available/lcwp-frontend.conf`**，链到 **`sites-enabled`**，并尽量移除自带的 **`default`** 站点，避免与 **`listen 80`** 冲突。  
- **无 `sites-enabled` 的发行版**：写入 **`/etc/nginx/conf.d/lcwp-frontend.conf`**。  
- 配置中含 **`Host` / `X-Real-IP` / `X-Forwarded-For` / `X-Forwarded-Proto`**，便于应用识别协议与客户端。  
- 执行 **`nginx -t`** 后 **`systemctl reload nginx`**（或 **`nginx -s reload`**）。

### 5.3 验收

- 浏览器访问 **`http://<域名>/`** 应出现与 **`http://<ECS公网>:3000/`** 相同的前端首页。  
- **`http://<域名>:8000/health`** 若需访问 API，本脚本**未**反代 **8000**；仍可用 **IP:8000** 或在 Nginx 上**另增** `location` / **独立 `server` 块**（不在本一键脚本范围内）。

### 5.4 HTTPS 与「选本地目录」下载

- **`http://域名/`**（含已备案、已解析的域名）在浏览器里仍是 **非安全上下文**，**不能**使用 **「选择本地目录保存」**。  
- 需 **`https://域名/`**（**TLS**）后，`window.isSecureContext` 才为 **true**（在受信任证书下），Chrome / Edge 等才开放 **File System Access**。  
- 更细的 Nginx / 证书示例可参考 **`后端部署指南_V1_Ubuntu22.04.md`** 中与 **nginx**、**certbot** 相关的章节。

### 5.5 启用 HTTPS（ECS：`certbot` + 已有 Nginx）

以下假定 ECS 为 **Debian/Ubuntu**，且已按 **§5.1～§5.2** 装好 **Nginx**、**`http://你的域名/`** 能打开前端首页。

#### 5.5.1 前置条件

| 项 | 说明 |
|----|------|
| **DNS** | 证书里要包含的每个名字（如 **`yideapi.com`**、**`www.yideapi.com`**）均需 **A 记录** 指向该 ECS **公网 IP**。 |
| **安全组** | 放行 **TCP 80**（Let’s Encrypt **HTTP-01** 校验与续期）、**TCP 443**（HTTPS 访问）。 |
| **Nginx 站点文件** | 一键脚本生成的一般为 **`/etc/nginx/sites-enabled/lcwp-frontend.conf`**（或 **`sites-available`** 下同名）。 |

#### 5.5.2 安装 Certbot（在 ECS 上执行）

```bash
sudo apt-get update
sudo apt-get install -y certbot python3-certbot-nginx
```

#### 5.5.3 申请证书并让 Certbot 改 Nginx

将示例域名换成你的；**几个 `-d` 就要在 Nginx 的 `server_name` 里写几个名字**（见 **§5.5.4**）：

```bash
sudo certbot --nginx -d yideapi.com -d www.yideapi.com
```

交互项说明：

- **邮箱**：用于续期失败等通知（请核对拼写，如 **`gmail.com`**）。  
- **同意服务条款**：选 **`Y`**。  
- **是否把邮箱提供给 EFF**：可任选，**不影响**签发。

成功后证书路径一般为（证书名与首个 **`-d`** 一致时）：

- **`/etc/letsencrypt/live/<首个域名>/fullchain.pem`**
- **`/etc/letsencrypt/live/<首个域名>/privkey.pem`**

#### 5.5.4 常见异常：`www` 与 `server_name` 不一致（安装阶段失败）

**现象（终端摘要，已在线上验证过）：**

- 先出现 **`Successfully received certificate`**，证书已写入 **`/etc/letsencrypt/live/...`**。  
- 再出现 **`Successfully deployed certificate for yideapi.com`** 到 **`lcwp-frontend.conf`**。  
- 随后 **`Could not install certificate`**，并提示：  
  **`Could not automatically find a matching server block for www.yideapi.com`**，建议执行 **`certbot install --cert-name yideapi.com`**。

**原因**：**`certbot --nginx`** 的 **`-d`** 列表里包含 **`www.yideapi.com`**，但当前 Nginx 里该站点 **`server_name`** 只有 **`yideapi.com`**，安装器无法为 **www** 找到匹配的 **`server` 块**。

**修复（需要 `www` 子域时）：**

1. 编辑站点配置（路径以本机为准）：  
   **`sudo nano /etc/nginx/sites-enabled/lcwp-frontend.conf`**  
2. 找到**本站点**下**每一个** **`server { ... }`**（常见为 **监听 80** 与 **监听 443** 各一块；若 Certbot 已拆成多块，**凡反代到前端的块都要改**），将：  
   **`server_name yideapi.com;`**  
   改为：  
   **`server_name yideapi.com www.yideapi.com;`**  
3. 校验并重载 Nginx：  

```bash
sudo nginx -t && sudo systemctl reload nginx
```

4. 让 Certbot 把证书挂到当前 Nginx 配置（证书已存在时仅执行 **install** 即可）：  

```bash
sudo certbot install --cert-name yideapi.com
```

（**`--cert-name`** 一般为 **`certbot certificates`** 中该证书行的 **`Certificate Name`**，多域名证书常以**首个 `-d` 域名**为名称，如 **`yideapi.com`**。）

**预防**：在本机执行 **`setup-nginx-reverse-proxy.bat`** 时，在 **`local-env.bat`** 里把 **`NGINX_SERVER_NAME`** 写成与 Certbot **完全一致**的主机名列表，例如：

```bat
set "NGINX_SERVER_NAME=yideapi.com www.yideapi.com"
```

再重新跑一键脚本或手工保持 **`server_name`** 与 **`certbot -d`** 一致。

**若不需要 `www`**：仅用 **`sudo certbot --nginx -d yideapi.com`**，且 Nginx **`server_name`** 只保留根域；已签出的多域名证书可用 **`certbot certificates`** 查看，是否删除/重建以运维策略为准。

#### 5.5.5 验收

```bash
sudo nginx -t && sudo systemctl reload nginx
```

浏览器访问 **`https://<你的域名>/`**，确认地址栏为**安全连接**。再在 **素材库** 下载：在 **Chrome / Edge** 下应可出现 **「选择本地目录保存」**（需 **HTTPS 安全上下文**）。

#### 5.5.6 续期与其它失败

- **续期**：Certbot 一般会注册 **systemd timer** 或 **cron**；自检： **`sudo certbot renew --dry-run`**。  
- **签发阶段失败**：多为 **80 未放行**、**域名未指向本机**、**本机防火墙（如 `ufw`）** 拦截 **80/443**。  
- **仅内网 / 不用公网 CA**：可自签 **`listen 443 ssl`**，浏览器会提示「不安全」；是否仍给 File System Access 视浏览器与是否手动信任而定，**生产对外**仍建议 **Let’s Encrypt** 等受信任证书。

## 6. 导入数据库：`仅导入数据库到ECS.bat`

在 **首次 `release-new-version.bat` 已成功**、远端已有 **`backend/.env`** 与 **`.venv`** 后执行。

1. 将 `DEPLOY_PG_DUMP_SQL` 设为本地 `.sql` 全路径，或在批处理提示时粘贴路径（可拖拽文件到窗口）。  
2. 运行 **`仅导入数据库到ECS.bat`**。  
3. 脚本会 **`scp`** SQL 到 ECS，在远端用 **`DATABASE_URL`** 执行 **`psql -f`**，再 **`alembic upgrade head`**，并尝试 **`systemctl restart light-content-api`**。

**注意：**

- 大库耗时会较长，勿关窗口。  
- 若 dump 含与当前 schema 冲突的对象，需由 DBA/开发评估是否先清库或使用目标一致的备份。  
- **`restore-ecs-database.ps1` 文件头注释** 若仍写「在 release 之后使用」与「首次应先 release」一致；以本文顺序为准。

## 7. 文件机：`start-nas-direct-services.bat`

在 **内网 Windows 文件机**（能映射 NAS、能访问 ECS **8000**）上：

1. 使用同一仓库根目录的 **`local-env.bat`**（或单独拷贝一份），保证 **`NAS_CLIENT_TOKEN`** 与 ECS **`NAS_CLIENT_TOKEN`** 一致。  
2. 推荐在 **`nas-client/nas-client-token.txt`** 写 **一行** token（无 `#` 注释行干扰），批处理会优先读该文件。  
3. 配置 **`nas-client/ecs-api-url.txt`**（或环境变量 **`NAS_API_BASE_URL`**）为 **`http://<ECS公网或可达IP>:8000`**。  
4. 运行 **`start-nas-direct-services.bat`**：会打开多个 PowerShell 窗口（全量 worker、缩略图 worker、LAN 9001、可选心跳）。

**验收：**

- Worker 窗口无持续 **401**。  
- 业务上能走通上传/下载/缩略图之一即可闭环。

## 8. 常见问题

| 现象 | 处理方向 |
|------|----------|
| SSH `Permission denied (publickey)` | 检查 **`DEPLOY_SSH_IDENTITY_FILE`**；或 **`DEPLOY_SSH_INTERACTIVE=1`** 用密码交互（不推荐生产）。 |
| 远端 `git clone` 失败 | ECS 上配置 **GitHub Deploy Key**（读私仓）；或 **`DEPLOY_GIT_CLONE_URL`** 指向可读 SSH URL。 |
| **`nas-jobs/poll` 401** | ECS **`NAS_CLIENT_TOKEN`** 与文件机一致；改后 **`systemctl restart light-content-api`**；可用 **`nas-client/verify-nas-token.ps1`** 自检。 |
| **`仅导入数据库` 报 `.env` 或 `.venv` 缺失** | 说明尚未成功完成步骤 **3** 的 **`release-new-version.bat`**，或 **`REMOTE_APP_DIR`** 与远端路径不一致。 |
| 本机 **`local-env.bat` 一闪退出** | 检查是否误用 **`exit`** 结束父批处理，应使用 **`exit /b 0`**。 |

## 9. 后续「一键更新」

日常迭代：在 **`local-env.bat`** 保持指向同一 ECS 的前提下，反复执行 **`release-new-version.bat`** 即可（含推送、`deploy.sh`、健康检查、可选 token 合并）。
