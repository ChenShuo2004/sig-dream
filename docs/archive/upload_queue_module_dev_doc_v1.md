# 上传队列模块开发文档 V1

版本：V1.0  
适用系统：轻量内容流程平台  
模块名称：上传队列  
开发优先级：系统设置、标签管理之后；素材库主页面之前  
目标：把上传队列从接口调试页改造成“上传入库工作台”，让用户完成选文件、填写入库信息、选择标签、上传、入库、查看进度。

---

# 一、结论

上传队列页面不是接口调试页，也不是素材库页面。

它的定位是：

```text
上传入库工作台
```

核心任务：

```text
选择文件
→ 填写入库标题 / 描述
→ 选择标签
→ 上传文件
→ 自动计算 hash
→ 自动查重
→ 入库 NAS
→ 写入素材资产记录
→ 写入标签关系
```

页面不要出现工程字段：

```text
Bearer token
标签 ID 输入框
sha256 手动输入框
upload_session_id
nas_job_id
nas_target_file
命令行调试说明
```

这些内容如需保留，只能放到：

```text
接口测试页面
开发者调试折叠面板
```

---

# 二、核心设计原则

## 1. 上传队列不是素材库

素材库负责：

```text
搜索
筛选
下载
复用
加入集合
查看详情
```

上传队列负责：

```text
上传
入库
打基础标签
处理上传状态
处理重复文件
```

不要把素材库的复杂筛选、最近下载、素材集合、下载区放到上传队列里。

---

## 2. 上传队列不是未整理页面

未整理页面处理的是：

```text
已经入库，并且带有“未整理”标签的素材
```

上传队列处理的是：

```text
还没正式入库，正在上传或待上传的文件
```

两者可以共用“标签选择面板”的交互，但页面目标不同。

---

## 3. 标签 ID 不给用户输入

用户只看：

```text
标签名称
```

系统内部保存：

```text
tag_id
```

删除当前页面中的：

```text
标签ID（逗号分隔，可选）
```

前端应通过标签选择组件保存 tag_id，而不是让用户手动输入 ID。

---

## 4. sha256 由系统自动计算

用户不应该手动填写：

```text
sha256
```

上传流程中，系统自动完成：

```text
读取文件
→ 计算 sha256
→ 查重
→ 显示查重结果
```

---

## 5. 入库标题默认来自文件名

规则：

```text
默认入库标题 = 原始文件名去掉扩展名
```

示例：

```text
原始文件名：理想L9充电口实拍.mp4
默认入库标题：理想L9充电口实拍
```

用户可以修改入库标题。

注意：

```text
入库标题不是标签
入库标题写入 material_assets.title
```

---

## 6. 没选标签自动进入未整理

入库规则：

```text
如果用户选择了至少 1 个标签：
  入库时写入所选标签
  不添加“未整理”标签

如果用户没有选择任何标签：
  入库时自动添加“未整理”标签
```

V1 不强制上传时必须打完整标签。

原因：

```text
上传阻力要低
未整理页面负责后续批量整理
```

# 三、页面结构

上传队列页面使用三栏结构：

```text
左侧：文件队列
中间：当前文件入库信息
右侧：标签选择面板
```

整体布局：

```text
┌──────────────────────────────────────────────┐
│ 上传队列｜已选 12 个文件｜上传中 3｜失败 1       │
│ [选择文件] [开始上传并入库] [暂停全部] [清空已完成] │
├───────────────┬─────────────────┬────────────┤
│ 左侧文件队列    │ 中间当前文件信息   │ 右侧标签面板 │
│               │                 │            │
│ 文件A 待上传    │ 预览              │ 内容对象     │
│ 文件B 上传中    │ 入库标题          │ 素材形态     │
│ 文件C 已完成    │ 入库描述          │ 用途         │
│ 文件D 失败      │ 文件信息          │ 场景         │
│               │ 上传进度          │ 内容主题     │
│               │ 入库状态          │             │
└───────────────┴─────────────────┴────────────┘
```

```text

失败数量
```

顶部按钮：

```text
选择文件

```

按钮规则：

```text

上传中 → 暂停全部可用
没有已完成任务 → 清空已完成禁用
```

# 八、标签应用规则

## 1. 应用到当前文件

按钮：

```text
应用标签到当前文件
```

执行：

```text
把右侧所选标签应用到当前选中的文件
```

---

## 2. 应用到全部文件

按钮：

```text
应用标签到全部文件
```

执行：

```text
把右侧所选标签应用到上传队列中的全部文件
```

适合一次上传同类素材。

---

## 3. 默认标签 + 单文件标签

V1 推荐采用追加逻辑：

```text
最终标签 = 默认标签 + 单文件标签
```

不要做覆盖逻辑。

原因：

```text
覆盖容易误删标签
追加更符合上传批量处理
```

---

# 九、入库标签规则

## 1. 已选择标签

如果文件有至少 1 个标签：

```text
上传完成后
→ 创建素材资产记录
→ 写入所选标签
→ 不添加“未整理”标签
```

---

## 2. 未选择标签

如果文件没有任何标签：

```text
上传完成后
→ 创建素材资产记录
→ 自动添加“未整理”标签
```

显示状态：

```text
已入库，进入未整理
```

提供入口：

```text
去未整理处理
```

---

## 3. 不要求用户输入“未整理”标签

“未整理”由系统自动处理。

不要让用户手动选择或输入：

```text
未整理 tag_id
未整理标签 ID
```

# 十、上传流程

上传流程：

```text
选择文件
→ 生成文件队列
→ 默认标题 = 文件名去扩展名
→ 用户可填写标题 / 描述 / 标签
→ 开始上传并入库
→ 系统计算 sha256
→ 系统查重
→ 分片上传
→ 合并分片
→ 写入 NAS
→ 创建素材资产记录
→ 写入标签关系
→ 生成缩略图 / 低清预览，异步
→ 写操作日志
```

---

# 十一、重复文件处理

## 1. 同 hash

系统提示：

```text
检测到重复文件，素材库中已存在相同内容。
```

操作：

```text
查看已有素材
取消上传
```

V1 默认规则：

```text
同 hash 不重复入库
```

---

## 2. 同名不同 hash

系统提示：

```text
检测到同名文件，但内容不同，可继续上传。
```

允许继续上传。

---

# 十二、上传完成结果

每个文件最终状态：

```text
已入库
已入库，进入未整理
上传失败
入库失败
```

## 1. 已入库

说明：

```text
上传成功，并且写入了用户选择的标签。
```

操作：

```text
查看素材
继续上传
```

---

## 2. 已入库，进入未整理

说明：

```text
上传成功，但没有选择标签，系统已自动添加“未整理”标签。
```

操作：

```text
去未整理处理
查看素材
```

---

## 3. 上传失败 / 入库失败

显示失败原因：

```text
网络中断
重复文件
NAS 写入失败
文件过大
权限不足
文件类型不支持
```

操作：

```text
重试
移除队列
```

# 十三、权限设计

权限完全走系统设置里的角色配置。

本模块使用权限点：

```text
asset.upload
```

规则：

```text
没有 asset.upload 权限：
- 不能进入上传队列，或进入后不能选择文件
- 不能开始上传
```

公网是否允许上传也走系统设置策略。

不要在上传队列模块中写死额外权限逻辑。

# 十四、API 设计

## 1. 初始化上传任务

```text
POST /uploads/init
```

请求：

```json
{
  "files": [
    {
      "client_file_id": "local-1",
      "original_filename": "理想L9充电口实拍.mp4",
      "file_size": 123456789,
      "mime_type": "video/mp4",
      "title": "理想L9充电口实拍",
      "description": "可选描述",
      "tag_ids": ["tag1", "tag2"]
    }
  ]
}
```

返回：

```json
{
  "upload_sessions": [
    {
      "client_file_id": "local-1",
      "upload_session_id": "uuid",
      "chunk_size": 52428800,
      "total_chunks": 10,
      "status": "pending"
    }
  ]
}
```

注意：

```text
upload_session_id 返回给前端内部使用
不要作为普通用户可编辑字段展示
```

---

## 2. 上传分片

```text
POST /uploads/{upload_session_id}/chunks/{chunk_index}
```

请求：

```text
multipart/form-data
chunk: binary
```

返回：

```json
{
  "upload_session_id": "uuid",
  "chunk_index": 0,
  "status": "uploaded"
}
```

---

## 3. 查询上传状态

```text
GET /uploads/{upload_session_id}/status
```

返回：

```json
{
  "upload_session_id": "uuid",
  "uploaded_chunks": [0, 1, 2],
  "total_chunks": 10,
  "status": "uploading"
}
```

---

## 4. 完成上传并入库

```text
POST /uploads/{upload_session_id}/complete
```

请求：

```json
{
  "title": "理想L9充电口实拍",
  "description": "可选描述",
  "tag_ids": ["tag1", "tag2"]
}
```

后端逻辑：

```text
1. 校验 asset.upload 权限
2. 合并分片
3. 计算 sha256
4. 查重
5. 写入 NAS
6. 创建 material_asset
7. 创建 material_file
8. 如果 tag_ids 非空：写入这些标签
9. 如果 tag_ids 为空：自动写入“未整理”标签
10. 创建缩略图 / 低清预览任务
11. 写操作日志
```

返回：

```json
{
  "asset_id": "uuid",
  "status": "stored",
  "tag_status": "tagged",
  "message": "已入库"
}
```

如果没有标签：

```json
{
  "asset_id": "uuid",
  "status": "stored",
  "tag_status": "unorganized",
  "message": "已入库，进入未整理"
}
```

---

## 5. 获取 active 标签

```text
GET /tags/active
```

返回 5 个分类下 active 标签：

```json
{
  "内容对象": [],
  "素材形态": [],
  "用途": [],
  "场景": [],
  "内容主题": []
}
```

不要返回：

```text
未整理
状态类标签
disabled 标签
merged 标签
deleted 标签
```

```text
这些内容如需保留，只能放到“接口测试”或“开发者调试折叠面板”。

十、重复文件处理

系统自动计算 sha256。

如果同 hash：
显示：
检测到重复文件，素材库中已存在相同内容。

操作：
- 查看已有素材
- 取消上传

如果同名但 hash 不同：
显示：
检测到同名文件，但内容不同，可继续上传。

十一、上传完成结果

上传完成后显示：
1. 已入库
2. 已入库，进入未整理
3. 上传失败
4. 入库失败

失败时显示失败原因和重试按钮。

十二、权限

上传权限走系统设置角色配置中的 asset.upload。
没有上传权限的用户不能进入上传队列或不能选择文件。
公网上传是否允许也走系统设置策略。

十三、操作日志

必须记录：
- 开始上传
- 上传成功
- 上传失败
- 入库成功
- 入库失败
- 入库时写入标签
- 入库时自动添加未整理标签
```

# 十九、验收标准

## 1. 页面验收

```text
页面不再显示 token、tag_id、sha256、nas_job_id 等调试字段
可以选择文件
可以看到文件队列
可以编辑入库标题
可以填写入库描述
可以在右侧选择五类标签
```

---

## 2. 标签验收

```text
用户选择标签名，不输入标签 ID
前端内部保存 tag_id
应用标签到当前文件生效
应用标签到全部文件生效
```

---

## 3. 入库验收

```text
有标签的文件入库后写入所选标签
无标签的文件入库后自动添加“未整理”标签
入库标题默认取文件名去扩展名
sha256 由系统自动计算
```

---

## 4. 查重验收

```text
同 hash 文件提示重复，不重复入库
同名不同 hash 文件允许上传并提醒
```

---

## 5. 权限验收

```text
无 asset.upload 权限不能上传
上传操作写入操作日志
入库标签写入操作日志
自动添加未整理标签写入操作日志
```

---

# 二十、最终定版

上传队列核心流程：

```text
选择文件
→ 默认生成入库标题
→ 用户可填写描述和标签
→ 系统自动计算 hash
→ 系统自动查重
→ 分片上传
→ 入库
→ 有标签则写入标签
→ 无标签则自动添加“未整理”
```

最关键原则：

```text
上传队列不是让用户填接口参数，而是让用户把文件变成合格素材资产。
```
