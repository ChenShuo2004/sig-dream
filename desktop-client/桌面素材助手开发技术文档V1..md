# 桌面素材助手开发技术文档 V1.1

版本：V1.1  
适用项目：轻量内容流程平台（Light Content Workflow Platform）  
新增目录：`desktop-client/`  
技术栈：Electron + Vite + React 19 + TypeScript + Tailwind CSS + HashRouter + electron-builder  
关键修正：当前项目 **没有正式设计和部署公网文件机 WAN**，因此桌面端 V1 下载选路明确为：

```text
V1：LAN 文件机直传 → ECS fallback 兜底
V2 预留：LAN → WAN → ECS fallback
```

---

## 一、结论

当前项目已经具备：

```text
Web 协作平台 frontend/
FastAPI 后端 backend/
PostgreSQL 数据库
NAS Worker / 文件机 nas-client/
素材库 / 素材集合 / 上传 / 下载选路 / 回收站 / 标签 / 操作日志
```

现在新增：

```text
desktop-client/
```

它不是替代 Web，而是补 Web 做不到的本地制作能力：

```text
本地缓存
真实本地路径
打开资源管理器 / Finder
复制本地路径
拖拽素材到剪映 / PR / 其他剪辑软件
```

桌面素材助手 V1 只要求支持：

```text
1. 局域网 LAN 文件机直传下载
2. LAN 不可用时，走 ECS prepare_download / download-cache 兜底
3. 未缓存素材拖拽时，自动下载到本地缓存，完成后再拖拽
```

不要求：

```text
公网文件机 WAN 可用
公网文件机域名 / HTTPS / 端口映射
public_download_base_url 必须存在
```

## 二、当前项目事实对齐

### 1. 当前技术栈

```text
前端：Next.js 15.5 + React 19 + TypeScript + Tailwind CSS 3
后端：FastAPI + SQLAlchemy 2 + PostgreSQL
任务 / 文件机：nas-client/worker.py + nas-client/download_server.py
迁移：Alembic
```

### 2. 当前 Web 访问方式

Web 前端使用：

```text
fetch("/api-proxy/...")
```

由 Next.js rewrite 到 FastAPI。

桌面端不走 `/api-proxy`，而是直接请求：

```text
{API_BASE_URL}/...
```

例如：

```text
http://<ECS_PUBLIC_IP>:8000/auth/login
http://<ECS_PUBLIC_IP>:8000/materials
```

### 3. 当前下载选路实际状态

当前后端存在 `download-route`，也可能返回 `public_download_base_url` 等字段。  
但当前项目尚未正式落实公网文件机，所以 desktop-client V1 不使用 WAN 作为必需路径。

实际 V1 选路：

```text
download-route
→ 探测 LAN 文件机 /health
→ LAN 可用：文件机直传下载
→ LAN 不可用：走 ECS fallback
```

其中 ECS fallback 使用现有：

```text
download-prepare
download-cache
```

## 三、为什么不把 WAN 写进 V1

公网文件机要稳定工作，需要额外工程条件：

```text
公网入口
域名
HTTPS 证书
端口映射 / 内网穿透
CORS
防火墙
限流
```

当前这些没有正式设计和部署，所以不能把 WAN 写成 V1 必需能力。

V1 文档中所有涉及下载顺序的地方，统一改为：

```text
LAN → ECS fallback
```

WAN 只作为未来增强：

```text
V2：LAN → WAN → ECS fallback
```

## 六、技术要求

### 1. Electron 安全配置

必须：

```text
nodeIntegration: false
contextIsolation: true
```

Renderer 只负责 UI。  
本地文件、下载、拖拽、打开文件夹等能力必须通过 Electron main 进程 + preload IPC 实现。

### 2. HashRouter

桌面端使用 HashRouter：

```text
#/login
#/materials
#/collections
#/cache
#/settings
```

原因：

```text
生产环境 loadFile(dist/index.html) 不依赖 dev server
```

### 3. Tailwind 深色视觉

`desktop-client/src/styles/globals.css` 参考 `frontend` 的深色工作台风格：

```text
深色背景
暗色卡片
细边框
按钮状态
输入框状态
滚动条样式
```

不要求完全复制 Web 页面，但视觉语言要一致。

## 八、本地缓存规则

### 1. 默认缓存目录

Windows：

```text
D:\LCP-Material-Cache
```

macOS：

```text
~/Movies/LCP-Material-Cache
```

### 2. 缓存文件命名

建议：

```text
{material_id}_{file_id}_{safe_original_filename}
```

必须清理非法字符：

```text
Windows：\ / : * ? " < > |
macOS：:
```

### 3. 缓存索引

V1 可用 JSON 文件保存缓存索引，后续再升级 SQLite。

字段：

```text
material_id
file_id
original_filename
local_path
file_size
sha256
cached_at
last_used_at
download_route
cache_status
error_message
```

`cache_status`：

```text
downloading
cached
failed
missing
corrupted
```

### 4. 缓存校验

使用缓存前必须检查：

```text
文件是否存在
文件大小是否一致
sha256，如有且需要
```

规则：

```text
文件存在且大小一致 → 可用
文件不存在 → missing
文件大小不一致 → corrupted，重新下载
sha256 不一致 → corrupted，重新下载
```

## 九、下载选路 V1

### 1. 下载入口

以下动作都走同一套缓存逻辑：

```text
点击缓存到本地
拖拽素材
打开所在文件夹
复制本地路径
```

如果素材未缓存，这些动作都先触发下载。

---

### 2. 下载流程

```text
检查本地缓存
→ 如果缓存可用，返回 local_path

如果未缓存：
→ 调用 POST /materials/{material_id}/files/{file_id}/download-route
→ 获取 ticket、lan_download_base_url、fallback 信息
→ 探测 LAN 文件机 /health
→ LAN 可用：从 LAN 文件机下载
→ LAN 不可用：走 ECS fallback
→ 下载完成写入本地缓存
→ 更新缓存索引
→ 返回 local_path
```

---

### 3. LAN 路径

条件：

```text
download-route 返回 lan_download_base_url
且 {lan_download_base_url}/health 可访问
```

下载：

```text
{lan_download_base_url}/download?ticket=...
```

由 Electron main 进程下载并写入本地缓存目录。

---

### 4. ECS fallback 路径

当 LAN 不可用时：

```text
调用 download-prepare
轮询 download-prepare/{job_id}
成功后下载 download-cache/{job_id}
写入本地缓存目录
```

说明：

```text
ECS fallback 是兜底路径，不是主路径。
```

---

### 5. WAN 暂不纳入 V1

V1 不要求：

```text
public_download_base_url 存在
公网文件机 /health 可用
公网文件机下载
```

如果后端返回 `public_download_base_url`：

```text
V1 可以忽略
或作为可选增强，但失败不得影响下载
```

不能因为 `public_download_base_url` 为空导致缓存失败。

## 十、拖拽逻辑

### 1. 基本原则

```text
拖拽到剪映必须使用真实本地文件路径。
不允许把远程 URL 直接拖给剪映。
```

### 2. 已缓存

```text
用户拖拽
→ 检查缓存可用
→ 使用 local_path 作为拖拽文件
```

### 3. 未缓存

```text
用户拖拽
→ 自动开始缓存
→ UI 显示：正在缓存到本地，完成后即可拖入剪映
→ 下载完成
→ 进入可拖拽状态
```

### 4. 缓存失败

```text
显示：缓存失败，请重试或检查网络
提供重新缓存按钮
```

### 5. 拖拽后

更新：

```text
last_used_at
```

可选：

```text
POST /materials/download-client-report
```

如后端字段不支持桌面拖拽语义，V1 先只做本地记录。

## 十七、Cursor Rules

请新增：

```text
.cursor/rules/desktop_client_integration.mdc
```

内容：

```md
# Desktop Client Integration Rules

本项目包含 Web 前端 frontend、FastAPI 后端 backend、NAS 文件机 nas-client，以及桌面素材助手 desktop-client。

desktop-client 是 Web 系统的桌面增强客户端，不是 Web 系统的替代品。

## 一、架构边界

1. frontend 负责团队协作、管理、标签、上传、未整理、回收站、操作日志、系统设置、教程中心和未来工作流。
2. desktop-client 只负责本地制作能力：素材查找、集合浏览、本地缓存、打开文件夹、复制路径、拖拽到剪映。
3. backend 是唯一业务写入入口。
4. desktop-client 不允许直接访问数据库。
5. desktop-client 不允许改变 NAS 真实文件路径。
6. desktop-client 不允许绕过 FastAPI 权限校验。

## 二、共享业务规则

1. 素材集合是引用关系，不是文件夹。
2. asset_collection_items 指向 materials / material_files。
3. 从集合移除素材，不删除素材库文件。
4. 删除集合，不删除素材库文件。
5. 未整理素材由“未整理”标签或零标签判定，不由 material.status 判定。
6. 标签分类来自 GET /tags/categories，不允许写死。
7. 下载统一通过 download-route。
8. V1 下载选路为 LAN → ECS fallback。
9. WAN 公网文件机仅为未来预留，不作为 V1 必需能力。
10. ECS 不作为大文件主路径中转，只作为兜底。
11. 缩略图 / 预览视频由 NAS Worker 异步 generate_derivatives 生成。

## 三、桌面端缓存规则

1. 拖拽到剪映必须使用本地真实文件路径。
2. 未缓存素材拖拽时，必须先自动下载到本地缓存。
3. 下载完成后才能拖拽。
4. 不允许把远程 URL 直接拖给外部软件。
5. 本地缓存目录默认：
   - Windows: D:\\LCP-Material-Cache
   - macOS: ~/Movies/LCP-Material-Cache
6. 缓存索引记录 material_id、file_id、local_path、sha256、file_size、cached_at、last_used_at。
7. 缓存文件存在时必须校验文件大小或 hash，避免损坏缓存被复用。

## 四、同时维护规则

凡是修改以下内容，必须同时检查 frontend 和 desktop-client：

1. API 路径
2. API 请求字段
3. API 响应字段
4. 登录鉴权
```

## 二十、Cursor 一键开发指令

```text
请在当前仓库新增 desktop-client/ 目录，开发桌面素材助手。

技术栈：
- Electron
- Vite
- React 19
- TypeScript
- Tailwind CSS
- HashRouter
- electron-builder

desktop-client 是现有 Web 素材系统的桌面增强客户端，不替代 frontend。
它主要补充浏览器做不到的本地能力：
- 本地缓存
- 真实文件路径
- 打开资源管理器 / Finder
- 复制本地路径
- 拖拽素材到剪映 / PR / 其他剪辑软件

必须保证：
1. Web 前端 frontend 可以继续正常使用。
2. 桌面素材助手 desktop-client 可以同时正常使用。
3. 两端共用同一套 FastAPI 后端、PostgreSQL 数据库、素材库、标签、集合、权限和下载选路逻辑。
4. 不得为了桌面端破坏 Web 端已有行为。
5. 不得为了 Web 端修改而忽略桌面端依赖。

重要修正：
当前项目没有正式设计和部署公网文件机 WAN。
因此 desktop-client V1 下载选路为：
LAN 文件机直传 → ECS fallback 兜底。

不要把 WAN / public_download_base_url 写成 V1 必需能力。
如果后端返回 public_download_base_url，可以先忽略或作为未来增强，但不能因为它为空导致下载失败。

桌面端拖拽逻辑必须是：
- 已缓存：直接拖拽本地文件路径
- 未缓存：自动下载到本地缓存，下载完成后进入可拖拽状态
- 下载失败：提示用户重新缓存
- 不允许把远程 URL 直接拖给剪映

大文件下载必须在 Electron main 进程执行。
Renderer 只负责 UI。
桌面端必须复用后端 download-route。
桌面端不能直接访问数据库。
桌面端不能移动 NAS 原文件。

请同时新增：
.cursor/rules/desktop_client_integration.mdc
并写入本文档中的规则。
```
