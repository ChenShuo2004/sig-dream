# 桌面素材助手：如何执行（运行）

本文说明在本机**安装依赖、启动开发版、构建生产资源、用 Electron 打开**的步骤。桌面端直连 FastAPI，**不使用** Web 的 `/api-proxy`。

---

## 一、环境要求

| 项 | 说明 |
|----|------|
| Node.js | 建议 **20+**（与仓库其它前端一致） |
| npm | 随 Node 安装即可 |
| 后端 | FastAPI 已启动，且你能访问其根地址（如 `http://127.0.0.1:8000`） |
| CORS | 开发时页面源为 `http://127.0.0.1:5173`，需在**后端**允许该 Origin，否则浏览器/Electron 内 fetch 会被拦截 |

---

## 二、一键执行（最省事）

本目录提供脚本：**若无 `node_modules` 会先执行 `npm install`，再启动 `npm run electron:dev`**（与下文「三、推荐：Electron 窗口运行」等价）。

### Windows

1. **推荐**：在资源管理器中进入 **`desktop-client`**，**双击 `一键运行.bat`**。  
   - **说明**：`.bat` 文件**仅含英文**，避免 `cmd.exe` 在中文系统下把 UTF-8 按 GBK 解析导致乱码、整段脚本失效。  
   - 实际逻辑在 **`run-desktop.ps1`**（纯 ASCII 文件名，避免 `-File` 路径乱码）；脚本会自动尝试把 **`Program Files\nodejs`** 等加入 `PATH`。  
2. **若仍无法启动**：在 `desktop-client` 打开终端，执行：
   ```powershell
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
   .\run-desktop.ps1
   ```

若提示找不到 `node` / `npm`，请安装 **Node.js LTS** 并勾选 **Add to PATH**，安装后**重新打开资源管理器**再双击。

### macOS / Linux

在终端中：

```bash
cd desktop-client
chmod +x 一键运行.sh
./一键运行.sh
```

### 与 npm 等价命令

已在 `package.json` 中配置 **`npm start`** → 与 **`npm run electron:dev`** 相同；在 `desktop-client` 目录下执行：

```bash
npm start
```

## 三、首次准备（安装依赖）

若已通过 **「二、一键执行」** 自动完成安装，可跳过本节。

```bash
cd desktop-client
npm install
```

若安装 **Electron** 时网络超时或失败，可查看本目录下的 **`.npmrc`**（已配置国内 `electron_mirror`）；仍失败时请关闭已打开的 Electron 窗口后重试 `npm install`。

---

## 四、推荐：Electron 窗口运行（开发）

一条命令同时启动 **Vite 开发服务器** 和 **Electron**（先等 `5173` 就绪再打开窗口）：

```bash
cd desktop-client
npm run electron:dev
```

预期现象：

1. 终端里 Vite 输出本地地址 `http://127.0.0.1:5173`。
2. 自动弹出 **桌面素材助手** 窗口。
3. 在窗口内：先填写 **API 根地址**（例如 `http://127.0.0.1:8000`）并**登录**；未登录前访问受保护路由会跳到登录页。

停止：在运行 `electron:dev` 的终端按 **Ctrl+C**（`concurrently` 会结束 Vite 与 Electron）。

---

## 五、仅用浏览器调试 UI（可选）

不启动 Electron，只跑 Vite，便于快速改界面：

```bash
cd desktop-client
npm run dev
```

浏览器打开：**`http://127.0.0.1:5173/`**  
路由为 **Hash**，例如：

- 登录：`http://127.0.0.1:5173/#/login`
- 素材库：`http://127.0.0.1:5173/#/materials`
- 桌面壳配置（可不登录）：`http://127.0.0.1:5173/#/desktop/app-config`

## 六、生产构建 + 用 Electron 加载本地页面

先打出静态资源到 `desktop-client/dist/`，再启动 Electron（主进程会 `loadFile(dist/index.html)`，不依赖开发服务器）：

```bash
cd desktop-client
npm run build
npm run electron:pack
```

用于验证「打包后的页面在壳里是否正常」。

### 6.1 打成 Windows / macOS 安装包

在 `desktop-client` 目录：

| 平台 | 命令 |
|------|------|
| **Windows（本机）** | 双击 **`打包应用程序.bat`**，或 `npm run dist:win` |
| **macOS（须在 Mac 上）** | `./打包应用程序-mac.sh`，或 `npm run dist:mac` |

产物目录：**`desktop-client/release/`**

- Windows：`桌面素材助手-0.1.0-win-x64.exe`（NSIS 安装程序）、`桌面素材助手-0.1.0-win-x64.zip`、以及 `win-unpacked/` 绿色版
- macOS：`桌面素材助手-0.1.0-mac-x64.dmg/.zip`、`arm64` 同理（需在 Mac 构建）

说明：**macOS 的 DMG 无法在纯 Windows 上交叉编译**，`打包应用程序.bat` 在本机会打 Windows 包，并提示在 Mac 上执行 `打包应用程序-mac.sh`。内网机若报 winCodeSign 符号链接错误，脚本已关闭自动签名（`signAndEditExecutable: false`）；也可开启 Windows **开发人员模式** 或以管理员重试。

**安装包内嵌配置**：`pack-desktop.ps1` 读取根目录 `local-env.bat` 的 **`SERVER_HOST`**（API）与 **`NAS_HOST` / `LCP_MATERIAL_ASSETS_ROOT`**（SMB 素材 UNC）。**不要**用 `DEPLOY_LAN_*` 的 IP 当 SMB 主机：HTTP 文件机常为 **<FILE_HTTP_HOST>:9001**，SMB 共享 **`nas-file`** 在 NAS **<NAS_SMB_HOST>**（与 `nas-client` Worker 默认一致）。

| 角色 | 典型 IP | 用途 |
|------|---------|------|
| ECS API | `SERVER_HOST`（如 <ECS_PUBLIC_IP>:8000） | 登录、元数据 |
| 局域网 HTTP 文件机 | <FILE_HTTP_HOST>:9001 | `prepare_download` 票据下载 |
| SMB 素材存储 | **<NAS_SMB_HOST>** `\\<NAS_SMB_HOST>\nas-file\material-assets` | 桌面拖放直读文件 |

根目录 `local-env.bat` 建议显式设置：

```bat
set "NAS_HOST=<NAS_SMB_HOST>"
set "NAS_SHARE=nas-file"
set "LCP_MATERIAL_ASSETS_ROOT=\\<NAS_SMB_HOST>\nas-file\material-assets"
set "DEPLOY_LAN_DOWNLOAD_BASE_URL=http://<FILE_HTTP_HOST>:9001"
```

### 6.2 发布到 GitHub 与客户端自动更新

1. 在 [GitHub Settings → Developer settings](https://github.com/settings/tokens) 创建 **Personal Access Token**（**不是** SSH 公钥指纹、也不是 `SHA256:` 摘要）：
   - **Classic**：勾选 **`repo`**（私有仓库）或 **`public_repo`**（公开仓库）
   - **Fine-grained**：对 `light_content_workflow_platform` 勾选 **Contents: Read and write**
   - 复制完整字符串，一般以 **`ghp_`** 或 **`github_pat_`** 开头（长度通常远大于 40）
2. 写入本机 **`local-env.bat`**（仓库根或 `desktop-client/`，已 gitignore）：
   - `set "GH_TOKEN=ghp_你的完整token"`
   - **说明**：`release-new-version.bat` 的 `git push` 走 **SSH 私钥**，与 `GH_TOKEN` 无关；只有发布桌面安装包到 Releases 才需要 PAT。
3. 先双击 **`验证GitHub令牌.bat`**，应看到 `GitHub API OK. Logged in as: 你的用户名`；若报 401 或「格式不像 PAT」，请重新生成 Token 再改 `local-env.bat`。
4. 再双击 **`打包并发布到GitHub.bat`**（或 `pack-desktop.ps1 -Platform win -PublishGitHub`）。发布前脚本会先调 GitHub API，避免打完包才发现 Token 无效。
5. 其它方式：PowerShell `$env:GH_TOKEN = "ghp_..."`；或 [GitHub CLI](https://cli.github.com/) `gh auth login`（脚本会读取 `gh auth token`）。
4. 在仓库 [Releases](https://github.com/ChenShuo2004/sig-dream/releases) 会出现新版本安装包。
5. 已安装的桌面客户端：打开 **本机连接与缓存** → **检查更新** → **下载更新** → **重启并安装**。

**私有仓库 404**：`releases.atom` 返回 404 表示客户端读不到 GitHub Releases。打包时须配置 **`GH_TOKEN`**，脚本会写入安装包内 `github-updater-token.txt`（仅 `contents: read` 的 Fine-grained Token 即可）；并确认 GitHub 上已有对应版本的 Release。

**局域网其他电脑拖放失败时**：在 **本机连接与缓存** 将 `material_assets_root` 设为本机可打开的 **UNC**（如 `\\<FILE_HTTP_HOST>\nas-file\material-assets`），登录后点 **同步素材元数据**，再拖放。勿使用仅某台电脑才有的 `Z:` 盘符。

**Windows 提示输入网络凭据 / 阻止来宾访问**：须用 NAS 账号登录 SMB。任选其一：
1. **安装版 0.1.6+**：直接启动 exe（打包时写入 `nas-smb-credentials.json` 则自动 SMB 登录）；一般**不必**单独运行映射 bat。
2. **仅拷贝 `desktop-client` 文件夹的电脑**：须包含同目录的 `ensure-nas-smb.ps1`、`_nas-share-map.ps1`；凭据用 `nas-smb-credentials.json`（复制 `nas-smb-credentials.example.json` 并填写，勿提交）或仓库根 `local-env.bat` 的 `NAS_PASSWORD`。
3. **开发机**：根目录 `local-env.bat` 有 `NAS_PASSWORD` 时，`一键运行.bat` 会自动执行 `ensure-nas-smb.ps1`。
4. 手动：资源管理器打开 `\\<FILE_HTTP_HOST>\nas-file`，输入 **NAS 账号**（如 `PA` / `<FILE_HTTP_HOST>\PA`），不是 Windows 登录密码。

**映射 bat 报 `'itignored' 不是内部或外部命令`**：旧版 bat 的 `REM Gitignored` 行会被 cmd 误解析；请用仓库最新 `映射NAS-Z盘.bat`（仅 ASCII 注释）。

**映射 bat 报 missing `nas-client\_nas-share-map.ps1`**：其它电脑未拷完整仓库；使用带 `desktop-client\_nas-share-map.ps1` 的版本，或只装正式安装包。

**Z: 映射报 1219**：UNC 已登录成功时可忽略 Z:（助手使用 UNC）；或先 `net use * /delete /y` 再映射。脚本在 UNC 成功时 exit 0。

## 七、首次使用配置顺序建议

1. **API 根地址**：在登录页填写，或先到 **`#/desktop/app-config`** 保存「API 根地址」；勿带尾部多余 `/`（程序会自动规整）。
2. **测试连接**：在设置页可点「测试连接」请求后端的 **`GET /health`**。
3. **登录**：用户名、密码与 Web 后台一致；登录成功后写入本机 `localStorage`（与 Web 使用相同键名时注意勿在同一浏览器配置里混用两套环境）。
4. **缓存目录**：在设置中可改；默认 Windows 为 `D:\LCP-Material-Cache`，macOS 为 `~/Movies/LCP-Material-Cache`（详见《桌面素材助手开发技术文档》）。

## 八、常见问题

| 现象 | 处理方向 |
|------|----------|
| 登录或列表请求失败、控制台报 CORS | 在后端为 `http://127.0.0.1:5173` 配置 CORS；生产壳若换 Origin 也需同步放行 |
| `npm install` 报 `EBUSY` 与 `electron` 目录 | 关闭所有 Electron / 占用 `node_modules` 的进程后重试 |
| 双击 `一键运行.bat` 乱码、`'l' 不是命令`、PowerShell `-File` 路径非法字符 | **原因**：`.bat` 为 UTF-8 且含中文时，`cmd` 常按 GBK 解析导致整段失效；`-File` 指向**中文文件名**的 `.ps1` 时路径会乱码。**处理**：已改为 **纯英文 `一键运行.bat` + `run-desktop.ps1`**；仍异常时执行 **`.\run-desktop.ps1`** 排障 |
| 双击后窗口一闪就关 | 多为 **PATH 无 node/npm**；`run-desktop.ps1` 会尝试 `Program Files\nodejs` 等；仍失败请终端运行 **`.\run-desktop.ps1`** 看完整输出 |
